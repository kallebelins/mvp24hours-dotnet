# Mvp24Hours documentation routing

Use this context when implementing or reviewing .NET solutions with Mvp24Hours.

## Retrieval order

1. Use the external Mvp24Hours MCP when its public endpoint is available.
2. Read canonical documentation under `docs/en-us/`.
3. Use `docs/en-us/guides/architecture/` for architecture choices only.
4. Verify exact APIs against `src/` and behavior against `src/Tests/`.

## Accuracy rules

- The current source targets `net10.0`; check release notes before assuming package 10.0.0 is published.
- Do not copy stale `9.*` package pins. Follow the consuming solution's package-version policy.
- For CQRS use Mvp24Hours APIs: `AddMvpMediator`, `IMediatorCommand<T>`, `IMediatorQuery<T>`, their handler interfaces, and `IMediator.SendAsync`.
- Prefer current `Program.cs`, native OpenAPI, `ILogger<T>`, OpenTelemetry, health checks, `TimeProvider`, and native resilience guidance.
- Canonical module documentation owns API/configuration facts. Architecture Guides explain why, boundaries, and solution shape.
- Former `ai-context/` pages are compatibility stubs. Do not route new work to them.
- Semantic Kernel, Semantic Kernel Graph, and Microsoft Agent Framework are external projects, not Mvp24Hours product modules.
